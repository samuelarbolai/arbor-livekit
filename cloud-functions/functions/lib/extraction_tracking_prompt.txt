# CONTEXT

The user has one or more behaviours they are tracking. Each behaviour has a unique `googleDocId`. The list of behaviours, with their conversational names, is provided below in the BEHAVIOURS block.

In the call, the agent walks through each behaviour and tries to surface three KPIs naturally — without using tool names or schema-speak. Your job is to read the conversation and fill the schema from what the user actually said.

# OUTPUT

A single JSON object keyed by `googleDocId`. Every behaviour listed in the BEHAVIOURS block MUST appear as a key. The value is an object with these exact fields:

  "<googleDocId>": {
    "relapse": true | false | null,
    "ritualFulfilled": true | false | null,
    "answeredCall": true | false | null,
    "ritualUsedOut": true | false
  },

# FIELD RULES

1. **relapse** — Did the user have a relapse on this behaviour today?
   - `true` if the user reported engaging in the behaviour they're trying to avoid (e.g. "I drank", "I rolled up", "yeah I scrolled all morning").
   - `false` if the user reported NOT engaging in it (e.g. "I didn't drink", "no I did not roll up", "I held the line").
   - `null` if the transcript never touches the question for this behaviour.
   - Only meaningful for avoidance/control behaviours. For pure positive-development behaviours (e.g. "morning meditation", "daily journaling") where there is nothing to relapse INTO, leave this `null` unless the user volunteered something specific.

2. **ritualFulfilled** — Did the user perform their ritual (the daily practice) today?
   - `true` if the user said they did the practice today.
   - `false` if the user said they skipped it.
   - `null` if the transcript never touches it.

3. **answeredCall** — Did the user pick up the coaching call for this behaviour today?
   - `true` if confirmed yes.
   - `false` if confirmed no.
   - `null` if not discussed.

4. **ritualUsedOut** — Has the user said they have OUTGROWN this specific behaviour and no longer need to track it?
   - `true` if they said something like "I don't need this one anymore", "this isn't a problem for me now", "I'm done with that one", or language equivalents.
   - `false` otherwise. Default is `false` — only set `true` on explicit user-driven retirement, never on inference.

# CROSS-KPI INFERENCE — IMPORTANT

The user is RARELY going to answer each KPI separately. They will usually pack multiple answers into one sentence. Capture every signal they give you. Two specific inference patterns:

- **Denial of the behaviour** (avoidance/control rituals): If the user says "I didn't [do the behaviour]" — e.g. "I didn't drink", "I did not roll up", "I held back today" — this should fill BOTH:
  - `relapse` = `false` (they didn't relapse), AND
  - `ritualFulfilled` = `true` (they did the work of holding the line — the ritual exists to support exactly this kind of day).

- **Affirmation of the practice** (positive-development rituals): If the user says "I did my meditation today" / "I journaled", this fills `ritualFulfilled` = `true`. Do NOT infer anything about `relapse` from this — they may have done the ritual and still had a relapse on the underlying behaviour.

If the user is ambiguous (e.g. "kind of", "sort of", "I tried"), leave the KPI as `null` rather than guessing.

# WHAT TO DO ABOUT THE BEHAVIOUR'S NAME

Each behaviour has a conversational name in the BEHAVIOURS block, but in the transcript the user and the agent may refer to it loosely ("it", "that one", "the morning thing"). Use the conversation order and the agent's transitions to figure out which behaviour the user is talking about. The agent typically walks through behaviours in the order listed in BEHAVIOURS; transitions like "and how about <name>?" mark a switch.

If the transcript is ambiguous about which behaviour a user statement belongs to, prefer the most recently asked-about behaviour and leave the others' KPIs `null`.

# WHAT IF THE CALL ENDED EARLY

If the user hung up partway through, or the conversation never got to a given behaviour, leave that behaviour's KPIs at their defaults (null / false for ritualUsedOut). Do not guess.
